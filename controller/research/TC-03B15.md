# TC-03B15 — timer update-source attribution and low-word continuity

Status: portable/source-handoff contract only. Target remains the 2027-28 Terps Racing EV torque-control project.

## Decision

For a software-extended STM32F405 timer timebase, proving that `URS=1` makes update interrupts overflow-only is useful but not sufficient.

RM0090 separates two questions: what can set UIF/request an update interrupt, and what can reset or reinitialize the low-word counter. With `URS=1`, software `UG` and trigger-driven reinitialization can be filtered out of the update-interrupt path, but they can still reinitialize the timer counter. The high word can therefore remain unchanged while the low word silently jumps, breaking continuity.

The source-specific gate needs both overflow-only interrupt attribution and proof that no non-overflow low-word reinitialization occurs during the evaluated window.

## Primary-source findings

ST's current STM32F405/415 documentation catalogue lists RM0090 v22.0, updated 29 May 2026.

RM0090's timer descriptions state:
- `URS=0`: overflow/underflow, software `UG`, and slave-mode update generation can generate update requests when enabled.
- `URS=1`: only overflow/underflow generates the update interrupt/DMA request.
- `UDIS=1`: update-event generation is disabled. The counter/prescaler can still be reinitialized by `UG` or hardware reset paths.
- UIF is set at overflow when `UDIS=0`; `UG`/trigger reinitialization can also set UIF when `URS=0` and `UDIS=0`.
- `UG` reinitializes the counter and prescaler.

## Portable truth-table result

A standard-library-only host reference enumerated 24 combinations of:
- URS in {0,1}
- UDIS in {0,1}
- UIE in {0,1}
- event in {overflow, software UG, trigger reset}

Important counterexamples:
- URS=0, UDIS=0, UIE=1 plus software UG: the low word reinitializes, UIF is set, and an update ISR can falsely count the software reinitialization as a hardware wrap.
- URS=1, UDIS=0, UIE=1 plus software UG: no false update interrupt occurs, but the low word still reinitializes, so the extended timestamp can become discontinuous.
- UDIS=1 plus hardware overflow: the extension loses the normal UIF/update-interrupt evidence it relies on.

## Source-specific worker packet

Prerequisites:
1. TC-03A/B0 identify and reproduce the exact firmware.
2. TC-03B11-13 establish the actual timer, rate, ARR/PSC, modulus and freshness window.
3. TC-03B14 applies if a software overflow extension is actually used.

Ordered actions:
1. Identify every write to the timer CR1, DIER, EGR, SMCR and CNT registers, including HAL/LL wrappers.
2. Record actual URS, UDIS and UIE values during the timestamp window.
3. Find every path that sets UG, changes slave/reset mode, or directly writes CNT.
4. Classify whether each path can execute during control/freshness measurement.
5. If a non-overflow low-word reset is possible, prove explicit epoch handling or reject the source as a continuous timebase.
6. Verify one high-word writer and one UIF-clear owner.
7. Then apply TC-03B14 overflow-to-service and snapshot-interleaving gates.
8. Preserve exact source revision, register-write locations and test receipts.

Stop on ambiguous register ownership, unmodeled URS/UDIS/UIE changes, possible silent low-word resets, false high-word increments, disabled overflow accounting, or any need for unapproved flashing/vehicle actuation.

No production firmware change, scheduler mutation, safety-system change, or vehicle action is authorized by this note.
