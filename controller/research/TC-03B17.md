# TC-03B17 - post-epoch critical-input recovery gate

Accessed 2026-10-03. Target remains the 2027-28 Terps Racing EV torque-control project.

## Decision

After a reviewed timebase discontinuity creates a new epoch, do not treat the control/freshness snapshot as coherent until every required critical input has been observed in the current epoch and passes its ordinary freshness/decode/unit/sign checks.

This closes a gap after TC-03B16. Rejecting direct timestamp arithmetic across epochs prevents one class of error, but a system can still accidentally mix individually "fresh" values that belong to different epochs. The recovery gate therefore blocks review until the complete required signal set has current-epoch evidence.

This gate is descriptive only. Passing it does not authorize torque, automatic recovery, shutdown changes, flashing, CAN transmission or vehicle operation.

## Frozen counterexample

Synthetic required signals:
- wheel_speed_fl
- wheel_speed_fr
- steering

Current epoch: 8.

The two wheel-speed samples are fresh in epoch 8. Steering is individually fresh but still belongs to epoch 7.

A naive check that looks only at each signal's freshness status reports all three fresh. The epoch-aware gate blocks because steering is cross-epoch.

The signal names are scenario labels, not a claim that the 2027-28 car exposes those exact interfaces.

## Current primary-source boundary

STMicroelectronics stm32f4xx-hal-driver master was rechecked on 2026-10-03. Current master still points to commit 1f6451c3e07728b4c830744de380e56bf5bc0026 from 2026-06-05.

At that revision:
- Src/stm32f4xx_hal_pwr.c documents Stop mode as stopping clocks in the 1.2 V domain and disabling PLL/HSI/HSE while preserving SRAM/register contents.
- Inc/stm32f4xx_ll_system.h exposes timer debug-freeze bits such as LL_DBGMCU_APB1_GRP1_TIM2_STOP, documented as stopping TIM2 when the core is halted.
- Inc/stm32f4xx_hal.h exposes matching HAL timer freeze/unfreeze macros.

Arm CMSIS continues to expose DWT CYCCNT as a uint32_t cycle-count register. These public mechanisms justify treating timebase continuity as source-specific evidence rather than an assumption. They do not prove any Terps Racing low-power path, timer choice, debug setting, or epoch implementation.

Formula SAE Series Resources still lists 2027 Formula SAE Rules Version V1 on 2026-10-03. No rule value is used as a timeout, recovery interval or control threshold in TC-03B17.

## Source-specific worker packet

Prerequisites:
1. TC-03A/B0 bind the exact firmware/build.
2. TC-03B11-B16 bind the selected timebase, rate, modulus, update ownership and epoch-transition rule.
3. TC-00 identifies the real critical input set.

Ordered actions:
1. Identify the exact state/event that increments or replaces the timestamp epoch.
2. Identify every critical input required before the torque-control path can be considered for recovery.
3. On epoch transition, invalidate cached pre-transition samples.
4. Require a current-epoch sample for every required input before recovery review.
5. Apply existing freshness, decode, unit and sign checks inside the same epoch.
6. Keep recovery eligibility separate from the action that actually resumes torque.
7. Log the epoch transition, first accepted sample per signal, and any blocker if the team authorizes instrumentation.
8. Test mixed old/new epochs, missing signals, stale current-epoch signals, and repeated epoch transitions in an offline/build fixture.

Stop conditions:
- critical signal set is guessed;
- epoch increment/reset ownership is unknown;
- any old-epoch sample can survive as valid input;
- recovery action is coupled directly to this evidence gate;
- validation would require unapproved flashing, hardware actuation or safety-system changes.

No firmware flashing, CAN traffic, HIL, dyno, track testing, Company Runtime mutation or vehicle actuation is authorized.
