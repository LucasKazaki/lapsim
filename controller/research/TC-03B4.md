# TC-03B4 — instrumentation-off noninterference gate

Status: portable/source-handoff contract only. Target remains the 2027-28 Terps Racing EV torque-control project.

## Decision

Before measuring an instrumentation-enabled firmware candidate, build the patched source once with the instrumentation feature explicitly disabled. Keep every non-source build input identical to the untouched TC-03B0 baseline.

The strongest first check is byte identity for the expected firmware artifacts. If the feature-OFF patched build differs, stop and investigate rather than assuming the guard is inert. Some toolchains can embed timestamps, absolute paths, or other nondeterministic metadata; if that occurs, preserve the differing artifacts and establish a reviewed equivalence method instead of silently weakening the gate.

## Required evidence

Bind the patch to:
- exact TC-03B0 baseline commit and patch commit;
- exact allowed changed paths and actual changed paths;
- compile-time feature guard present and default OFF;
- clean `git diff --check`;
- same build command, working directory, toolchain identity/version, optimization, and linker-script digest;
- same expected artifact path set;
- SHA-256 and byte size for each baseline and feature-OFF artifact;
- explicit build-only scope: no hardware access, flashing, or vehicle actuation.

GNU GCC's current C preprocessor documentation states that `#if`/`#ifdef` conditionals decide at compile time whether controlled text is included in the token stream. This supports a compile-time-disabled instrumentation block as a generic first implementation pattern when the team's real toolchain supports it. Git's current `git diff` documentation provides the source-control basis for exact patch-scope and whitespace/error checking. These are generic mechanisms, not Terps Racing firmware evidence.

## Gate

`disabled_noninterference_pass` requires:
1. baseline and feature-OFF builds both succeed;
2. all non-source build inputs above match;
3. patch base matches the baseline and the receipt binds the patch commit;
4. every changed path is within reviewed instrumentation scope;
5. feature guard exists and defaults off;
6. diff check is clean;
7. neither build exceeds build-only scope;
8. artifact path sets match;
9. hashes and byte sizes match.

Passing this gate only permits the next measurement step: build the same reviewed source with instrumentation enabled and collect TC-03B1 memory, TC-03B2 logging-loss/capacity, and TC-03B3 timing evidence. It does not establish independent review, safety, rule compliance, or vehicle acceptance.

## Worker packet

Prerequisites:
- TC-03A team evidence complete;
- TC-03B0 untouched build reproducible;
- reviewed instrumentation-only path allowlist.

Ordered actions:
1. retain baseline TC-03B0 receipt and hashes;
2. add the smallest instrumentation patch behind one compile-time flag that is OFF by default;
3. retain `git diff --check` and exact changed paths;
4. build the patch with instrumentation OFF using unchanged build inputs;
5. compare artifact path set, SHA-256 hashes, and sizes;
6. proceed to instrumentation-ON B1/B2/B3 measurements only after the disabled-build gate passes;
7. otherwise preserve the discrepancy and stop.

No firmware flashing, hardware access, CAN traffic, HIL, dyno, track test, scheduler mutation, safety-system change, or vehicle actuation is authorized.
