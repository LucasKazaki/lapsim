# Racing Terps LapSim: team demo brief

**Purpose:** show what the current desktop simulator calculates, what the optional racing-line mode changes, and which team measurements are still needed before using a result for a car or course decision.

For a fresh Windows clone, run `setup_lapsim.cmd` once before this walkthrough; it creates the virtual environment and checks the desktop display and bundled course.

## Five-minute walkthrough

1. Launch `launch_lapsim.cmd`, select the **Prius benchmark**, and leave **Fused GNSS/IMU · default** and **Centerline (default)** selected. Run one lap. The Driver view shows the latest accepted model step while the solve runs, then plays the completed result. Read the lap time, speed, energy, lateral acceleration, and entry/exit speed boxes; point out the saved run ID. Scrub the Driver view to show how the **cell model values** boxes hold each accepted cell's torque/brake requests, achieved forces, longitudinal acceleration, and signed battery power. The next-entry ceiling is one braking constraint, not the controller's complete target. Different seam speeds mean this is one initial-condition lap, not a periodic steady-state prediction.
2. Open **Model notes** and point out the Analysis course warning. If the separate ENME408 intake package is installed locally, show **Source data** too; a fresh clone does not include that package. The default recording's x/y drawing and saved solver curvature are separate, inconsistent channels: prescribed turn is 3.657937 rad versus 6.283185 rad of map winding; integrating the saved curvature leaves a 542.633 m closure gap. This course has no surveyed left/right widths.
3. In **Course**, choose **Synthetic loop · AI demo**. It is a 195.398224 m rounded rectangle with four 12 m radius quarter-circle arcs and an *assumed* ±3 m corridor. Set the desktop Prius torque request to **80% (enter 80)**, which is model fraction 0.8, leave **Assumed road grip** at **100%**, choose **AI racing line (experimental)**, and run. The current speed-periodic model gives an eligible **16.8855728415 s** geometric baseline, **15.6249368146 s** half-offset path, and **14.5566299045 s** 0.95-offset path. The 0.95 path passes its continuous scalar clearance audit with a conservative **0.05339622659 m** minimum clearance bound and is selected with a **2.3289429370 s** modeled lead. The full-offset path exceeds the assumed corridor at an evaluated point by **0.0406357308 m**, so its lap calculation is skipped and it has no time or replay. Show **Compare path numbers** and replay the completed baseline, half, and 0.95 paths in Driver view. Describe this as an executable software example, not a surveyed Formula SAE track or validated team-car gain.
4. Switch back to **Fused GNSS/IMU · default**; changing course clears the previous result and replay. Keep AI mode; enter Prius torque request **100% (enter 100)**, assumed half-width **2.0 m**, vehicle width **1.78308 m**, safety margin **0.3 m**, and assumed road grip **100%** to reproduce the diagnostic example below. The planner tests full and half offsets first, then one bounded fourth strength with the same car and physics, at most two passes per path and eight passes total. Its modeled-path audit evaluates four positions per modeled cell plus every source-corridor cell boundary and midpoint, then bounds lateral clearance between evaluations with adaptive subdivision. An unresolved interval fails the audit; shared boundaries use the narrower adjacent width, and integrated position must close within 0.01 m. Here the processed baseline fails, so the fourth strength falls back to 0.75: completed times are starred diagnostics, the difference is blank, **Compare path numbers** is disabled, and no AI winner is selected. **Replay lap** can still inspect those diagnostic runs. A ranked candidate also needs a closed speed seam within 0.005 m/s and a modeled gain strictly greater than the provisional 0.05 s margin.
5. Switch **Driving path** back to **Centerline (default)**, then use **Run comparison** to run two car profiles at the same selected centerline settings and a shared feasible rolling-start speed. Read B-minus-A values, the common start, each car's finish/seam speed, and the saved IDs; then switch between A and B in Driver view's **Replay lap** menu. The profiles can be edited and saved without source-code changes, but the source-backed Terps entries remain partial working scenarios. This is still one initial-condition lap per car, not a steady-state prediction.
6. Open **Timed sessions · WIP**. Explain that a versioned car and controller, live driving against a ghost, complete session capture, and linked report are the next-stage contract; the tab deliberately cannot start a session yet. A separate Python checker can already rerun a completed saved lap's cell controls through the engineering model and report numerical differences under declared tolerances. It is not a timed-session or measured-car validation feature.

If there is time, return to the synthetic course and repeat a run at assumed
road grip **80%**. The setting uniformly scales the selected tire model's
force capacities, so describe the difference as a model sensitivity to one
assumption. Restore **100%** before citing the benchmark above. The multiplier
is saved with the run and restored by the engineering replay checker; it is
not measured surface grip, weather, or a spatial patch. Editing it clears the
old on-screen result and replay before another run.

The car and path comparison popups display the selected course label; an open
popup retains that label if the main course choice changes.

## What the optional racer actually does

It is a deterministic, offline path planner. It minimizes a geometric curvature-and-length objective within entered clearances, rejects invalid paths, and checks up to four paths with at most two physics passes each. After baseline, full, and half, it fits one convex quadratic only if all three audits and times are eligible and half beats both endpoints by more than 0.05 s. When full fails its audit but eligible half clearly wins, it screens stronger offsets using geometry and requires 0.02 m of certified scalar clearance before spending the fourth physics trial. An invalid candidate path is skipped before physics when the processed baseline is valid. Other cases use the 0.75 fallback. This is bounded car-specific probing, not learning. An **eligible comparison time** requires a completed lap, a closed speed seam, and a certified continuous normal-coordinate clearance inequality plus position closure. The optional synthetic loop has eligible baseline, half, and 0.95 paths; the default fused course's assumed-corridor paths fail despite completed model laps. The scalar certificate follows the supplied piecewise-width model; it is not a swept-body, world-frame containment, or surveyed cone-clearance certificate. The car and pack state still change across the lap. It does not learn from laps, steer a simulated car, see cones, or respond to traffic. The default centerline calculation does not run the planner. The Driver view is a top-down **reference-path** display with model speed and lateral acceleration, not a measured vehicle pose or a first-person camera.

## Evidence to show, and how to phrase it

- Show a saved run's input profile, source-course ID and synthetic flag where applicable, solver grid, actual lap start speed, course geometry, completion status, entry/exit speeds, telemetry, and content ID. Follow the primary AI record's `baseline_record` and `candidate_trials[].run_id` links to inspect each completed path's own telemetry and exact solver grid; `selected_result` refers to the primary file itself. For an engineer's follow-up, `replay_lap_record()` checks a completed v2 record's saved cell commands against the current model and reports numeric agreement separately from source/runtime differences. A record hash alone does not establish that agreement. The lap event and replay reject cells whose requested or achieved curvature differs from prescribed curvature by more than the default 1e-9 1/m tolerance; they do not verify x/y map following or cone clearance.
- Show the AI result's assumed corridor, observed excess, conservative minimum clearance bound when certified, and seam gap. On the default fused course, the assumed ±2 m Prius example used a 1.78308 m car width and 0.3 m margin, rather than the desktop's initial 1.8 m and 0.2 m fields. Baseline/full/half/three-quarter completed in 87.618366/87.377773/87.403816/87.3655968872 s but exceeded the usable corridor by 0.095506/0.908195/0.501981/0.705117 m; their times are starred, their difference blank, and their records diagnostic. In the primary AI record, read `settings.path_planning.fourth_strength_policy` and `settings.path_planning.candidate_trials[].offset_strength` with each audit/time before describing which fourth path ran or whether it was eligible. Each linked candidate record states its own `settings.path_planning.offset_strength`; completed diagnostic paths are saved and replayable even though their times are ineligible for ranking. On the synthetic loop, explain that the eligible 0.95-offset **2.3289429370 s** modeled lead proves this code path can produce a ranked result on a controlled example, not that it predicts a competition gain. Its full-offset path fails by **0.0406357308 m** at an evaluated point and therefore has no modeled time or saved run.
- Show the course geometry warning and the engineering handoff. The report gives the equations, Python data flow, test evidence, known mismatches, and unimplemented features.
- Show **Import course…** as the team-data entry point. A coherent, closed,
  versioned course bundle is validated and saved in the local catalog; the
  importer refuses to re-label the inconsistent fused recording as a coherent
  new course. An imported v1 course still has assumed AI width and no surveyed
  cone boundary. Its saved run separates source bundle/geometry hashes from
  the actual solver-grid hash; see the [bundle format](course_bundle_format.md).
- If showing a failed run record, read its `accepted_*` fields alongside the
  attempted terminal state and failed lap/cell index. The attempted state can
  be one rejected cell ahead of saved telemetry and is not a lap result.

## Data to request from the team

Ask for a surveyed centerline with left/right cone or pavement boundaries, a consistent distance/heading/curvature reconstruction, and the 2026–27 car's controlled revision of mass, wheelbase, track widths, tire force data, powertrain and battery limits, brake behavior, aero, and measured logs with stated test conditions. Those inputs matter more than a larger AI search or a learned driving policy at this stage.
