# Racing Terps LapSim: team demo brief

**Purpose:** show what the current desktop simulator calculates, what the optional racing-line mode changes, and which team measurements are still needed before using a result for a car or course decision.

## Five-minute walkthrough

1. Launch `launch_lapsim.cmd`, select the **Prius benchmark**, and leave **Fused GNSS/IMU · default** and **Centerline (default)** selected. Run one lap. The Driver view shows the latest accepted model step while the solve runs, then plays the completed result. Read the lap time, speed, energy, lateral acceleration, and entry/exit speed boxes; point out the saved run ID. Different seam speeds mean this is one initial-condition lap, not a periodic steady-state prediction.
2. Open **Source data / model notes** and the course warning. The default recording's x/y drawing and saved solver curvature are separate, inconsistent channels: prescribed turn is 3.657937 rad versus 6.283185 rad of map winding; integrating the saved curvature leaves a 542.633 m closure gap. This course has no surveyed left/right widths.
3. In **Course**, choose **Synthetic loop · AI demo**. It is a 195.398224 m rounded rectangle with four 12 m radius quarter-circle arcs and an *assumed* ±3 m corridor. Set Prius torque request to **0.8**, choose **AI racing line (experimental)**, and run. The current speed-periodic model gives an eligible **16.8855728415 s** geometric baseline, **15.6242848232 s** half-offset path, and **15.0077244060 s** three-quarter-offset path. The three-quarter path passes its sampled audit and is selected with a **1.8778484355 s** modeled lead. The numerically quicker full-offset trial is diagnostic because it exceeds the sampled corridor by **0.0406357247 m**. Show **Compare path numbers** and the two Driver view replays. Describe this as an executable software example, not a surveyed Formula SAE track or validated team-car gain.
4. Switch back to **Fused GNSS/IMU · default**; changing course clears the previous result and replay. Keep AI mode and enter the declared course and vehicle-width assumptions. The planner tests full, half, and three-quarter offsets with the same car and physics, at most two bounded passes per path and eight passes total. Its modeled-path screen samples four positions per modeled cell plus every source-corridor cell boundary and midpoint against assumed clearance, using the narrower adjacent width at shared boundaries, and requires position closure within 0.01 m. Here the processed baseline fails: completed times are starred diagnostics, the difference is blank, **Compare path numbers** is disabled, and no AI winner is selected. **Replay lap** can still inspect those diagnostic runs. A ranked candidate also needs a closed speed seam within 0.005 m/s and a modeled gain strictly greater than the provisional 0.05 s margin.
5. Use **Run comparison** to run two car profiles at the same selected centerline settings. Read B-minus-A values and the saved IDs, then switch between A and B in Driver view's **Replay lap** menu. The profiles can be edited and saved without source-code changes, but the source-backed Terps entries remain partial working scenarios.
6. Open **Timed sessions · WIP**. Explain that a versioned car and controller, live driving against a ghost, complete session capture, and linked report are the next-stage contract; the tab deliberately cannot start a session yet. A separate Python checker can already rerun a completed saved lap's cell controls through the engineering model and report numerical differences under declared tolerances. It is not a timed-session or measured-car validation feature.

The car and path comparison popups display the selected course label; an open
popup retains that label if the main course choice changes.

## What the optional racer actually does

It is a deterministic, offline path planner. It minimizes a geometric curvature-and-length objective within entered clearances, rejects invalid paths, and checks up to four paths with at most two physics passes each. An **eligible comparison time** requires a completed lap, a closed speed seam, and a sampled modeled-path check of usable clearance and position closure. The optional synthetic loop has eligible baseline, half, and three-quarter paths; the default fused course's assumed-corridor paths fail despite completed model laps. The sample screen is not a continuous swept-body or surveyed cone-clearance certificate. The car and pack state still change across the lap. It does not learn from laps, steer a simulated car, see cones, or respond to traffic. The default centerline calculation does not run the planner. The Driver view is a top-down **reference-path** display with model speed and lateral acceleration, not a measured vehicle pose or a first-person camera.

## Evidence to show, and how to phrase it

- Show a saved run's input profile, source-course ID and synthetic flag where applicable, solver grid, actual lap start speed, course geometry, completion status, entry/exit speeds, telemetry, and content ID. Open its linked AI counterpart to inspect both completed paths. For an engineer's follow-up, `replay_lap_record()` checks a completed v2 record's saved cell commands against the current model and reports numeric agreement separately from source/runtime differences. A record hash alone does not establish that agreement. The lap event and replay reject cells whose requested or achieved curvature differs from prescribed curvature by more than the default 1e-9 1/m tolerance; they do not verify x/y map following or cone clearance.
- Show the AI result's assumed corridor, sampled excess and seam gap. On the default fused course, the assumed ±2 m Prius example used a 1.78308 m car width and 0.3 m margin, rather than the desktop's initial 1.8 m and 0.2 m fields. Baseline/full/half/three-quarter completed in 87.618366/87.377773/87.403816/87.3655968872 s but exceeded the usable corridor by 0.095506/0.908195/0.501981/0.705117 m; their times are starred, their difference blank, and their records diagnostic. On the synthetic loop, explain that the eligible three-quarter **1.8778484355 s** modeled lead proves this code path can produce a ranked result on a controlled example, not that it predicts a competition gain. Its full-offset trial is ineligible by **0.0406357247 m** of sampled corridor excess.
- Show the course geometry warning and the engineering handoff. The report gives the equations, Python data flow, test evidence, known mismatches, and unimplemented features.

## Data to request from the team

Ask for a surveyed centerline with left/right cone or pavement boundaries, a consistent distance/heading/curvature reconstruction, and the 2026–27 car's controlled revision of mass, wheelbase, track widths, tire force data, powertrain and battery limits, brake behavior, aero, and measured logs with stated test conditions. Those inputs matter more than a larger AI search or a learned driving policy at this stage.
